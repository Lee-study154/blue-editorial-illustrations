# 构图与内容转译

## 从抽象文字到画面

每张图使用同一条转译链：

`核心判断 -> 物理动词 -> 低科技物件/环境 -> IP 动作 -> 结果状态`

例如：“把零散信息变成演示” -> 整理/分拣 -> 桌面、纸张与展示卡 -> IP 把纸推向有序结果。

先找动词，再选物件。不先画箭头、框和节点。

## 原创隐喻生成与判断

1. 从当前命题找出一个物理动词，例如接、量、压、折、筛、托、回收，而不是先挑一张已有场景。
2. 用 1-2 个低科技主物件承载关系；其余道具只解释原因、过程或结果。每张优先选择一种结构类型。
3. 让 IP 亲自改变物件状态。遮掉标注后，动作与结果仍应解释命题；去掉 IP 的动作后，关键转换应无法发生，否则人物只是装饰。

示例只作低频风格校准，不是默认构图输入。用户明确要求沿用某张图时，锁定该图的构图；用户提供新概念时，重新选择物件和动作，不默认复用散页/展示稿、缝带、抬梁、分拣架、工作台、验证门、台阶放大镜或轨道夹具。相同主题也可换新隐喻：反馈闭环不必画工作带，可以画 IP 按上轮批注修整下一轮样件。

整组规划时同时检查核心命题与主动作是否重复；文件不同、标注不同不等于内容不同。近似主题必须有清楚不同的状态转换。

## Shot list 必备字段

| 字段 | 内容 |
| --- | --- |
| 位置 | 对应章节或幻灯片 |
| 核心命题 | 读者应在 1 秒内理解的一件事 |
| 结构类型 | Workflow、系统局部、前后对照、角色状态、概念隐喻、方法分层、地图路线或小漫画分镜 |
| 物理隐喻 | 一个主物件或场景逻辑 |
| IP 动作 | 人物正在做的可见动作 |
| 人数 | 单人、双人或 3-5 人 |
| 环境道具 | 最多 3-7 个服务叙事的元素 |
| 图内标注 | 1-4 个逐字确定的短词；各自指向的动作/物件和手写位置 |
| 安全留白 | 左、右、上或不覆盖；HTML 标题与正文可用范围 |
| 蓝色焦点 | 蓝色用在哪个核心人/物/结果 |

## HTML 演示安全留白

生成图和 HTML 布局使用同一个方向决策。插画作为整页背景视觉层，不放进装饰卡片。

### 左文右图

- 图像主体放在右侧 50%-65%。
- 左侧保留至少 35%-42% 安全留白。
- 主动作和手势不进入标题区。

### 左图右文

- 主体放左侧，右侧保留 36%-44% 安全留白。
- 视线和动作方向可朝向文字，形成视觉连接。

### 上文下图

- 顶部保留 25%-32% 的宽区域。
- 人物和环境沿下部水平展开，适合多人与环境场景。

### 中心画面

- 适合封面、过渡页和纯视觉页。
- 不在主体上叠放正文；需要标题时放在外围留白。

图内标注贴近动作、物件或结果，随插画一起生成，不能占用 HTML 安全留白或压住脸、手与关键物件。HTML 的标题和正文保持 DOM 文字，不烧入图片。图像使用固定 16:9 尺寸和 `object-fit: cover` 或等效满页布局；文字容器与 shot list 中的安全区一致。

## 基础场景模式

### Workflow 流程

适合：输入 -> 处理 -> 输出、生产链和交付链。

构图：把流向变成连续的物理空间，IP 在中间的关键转换点操作；不画成一排方框加箭头。

### 系统局部

适合：来源、筛选、存储、渲染、代理等局部结构。

构图：只保留 3-5 个核心物件，让 IP 操作其中最重要的一个。

### 单人操作

适合：整理、分拣、转换、修补、探索、取舍。

构图：IP 与一个主物件形成大动作，其他道具只交代原因和结果。

### 双人交接

适合：协作、交付、反馈、误解、博弈、前后对照。

构图：两个 IP 分据一条对角线或一个共同桌面，中间只有一个交互物。

### 多人环境

适合：团队、社区、分工、系统同步、多角色状态。

构图：用 3-5 个 IP 构成前中后层，共享一个环境轴，如长桌、工作台、楼梯、书架、车间或房间。每人动作不同，但都服务同一个核心状态。涉及桌面或工作台时，明确层次顺序：人物在桌后，桌面是连续的前景遮挡平面，腿脚落在桌下地面层；手臂可以越过桌沿完成动作，但躯干、腿脚不能穿过桌面或与桌腿融合。

### 前后对照

适合：混乱/有序、阻塞/流动、负担/轻盈、孤立/协作。

构图：用一个连续环境或物件表现两种状态，不用规整分割线做 PPT 对比表。

### 角色状态

适合：焦虑、阻塞、工具过多、从卡住到运转。

构图：用 2-4 个短状态或同一 IP 的连续动作，保留一个共享环境轴。

### 概念隐喻

适合：看不见的系统、转化、循环、风险、筛选、沉淀。

构图：选一个低科技主物件，如压机、漏斗、抽屉、门、梯子、水管、秤或书架。IP 正在使用它，不是在旁边指讲。

### 方法分层

适合：能力栈、方法论、系统层级和逐层构建。

构图：用林立的抽屉、台阶、脚手架或堆叠工作台表现层级；IP 在搬、搭、对齐或修补。

### 地图路线

适合：从想法到上线、用户旅程、学习路线和内容承接。

构图：路线是一条真实可行走、牵引或铺设的路径，节点少而清楚，不画导航 UI。

### 小漫画分镜

适合：失败到成功、使用前后、过程吐槽和状态变化。

构图：用 2-4 个小场景，每格只有一个动作；分镜之间保留白底，不加粗重漫画框。

## 反信息图原则

- 一张图只保留一条主动作链，不把文稿缩成全部节点。
- 不在图里放章节标题、长文字、完整图表或 UI 框；短手写标注是画面元素，不做胶囊标签。
- 不用密集箭头解释关系；用姿态、物件位置、遮挡和结果形状表达。
- 元素足够让读者看懂后就停止增加。
